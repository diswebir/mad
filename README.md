# مدرسه‌یار — سامانه مدیریت مدرسه با Node.js · نسخه ۱.۳.۰

مدرسه‌یار یک پنل فارسی و راست‌چین ماژولار برای مدیریت مدرسه، معلم‌ها، کلاس‌ها و پرونده دانش‌آموزان است. نسخهٔ ۱.۳.۰ برنامهٔ هفتگی را به‌صورت مرکزی و قابل‌پیکربندی مدیریت می‌کند: مدیر روزهای آموزشی و ساعت هر زنگ را تعیین می‌کند، برای یک کلاس چند زنگ در روز می‌چیند، و برای هر درس/جلسه دبیر جداگانه می‌گمارد. برنامه بر پایهٔ سال تحصیلی ذخیره و برای مدیر، دبیر، دانش‌آموز و ولی با محدودهٔ دسترسی همان نقش نمایش داده می‌شود. ورود یک‌بارمصرف پیامکی IPPanel، انتخاب سیاست ورود مدیر، قفل کامل ویزارد پس از نصب و سخت‌سازی امنیت احراز هویت نسخهٔ پیشین نیز حفظ شده‌اند. برنامه با Node.js و بدون فریم‌ورک فرانت‌اند ساخته شده، معماری MVC/لایه‌ای دارد و برای اجرای Node.js در cPanel آماده است. رابط کاربری از فونت **Vazirmatn** استفاده می‌کند و برای حالت نمایشی، داده نمونه واقعی دارد. فایل‌های فونت WOFF2 در خود پروژه قرار دارند (مجوز SIL Open Font License) و برای نمایش فارسی به سرویس بیرونی وابسته نیستند.

## اجرای محلی

نیازمندی: Node.js نسخه ۱۸.۱۷ یا بالاتر و npm.

```bash
npm install
npm run dev
```

سپس `http://localhost:3000` را باز کنید. در حالت `dev` برنامه با داده‌های نمونه و ورود نمایشی اجرا می‌شود.

### حساب‌های نمونه

| نقش | نام کاربری | گذرواژه |
|---|---|---|
| مدیر مدرسه | `admin` | `admin123` |
| معلم | `ahmadi` | `teacher123` |
| دانش‌آموز | `sara` | `student123` |
| ولی دانش‌آموز | `maryam` | `parent123` |

این گذرواژه‌ها فقط برای محیط نمایشی هستند. از `npm run dev` یا `DEMO_MODE=1` روی هاست عمومی استفاده نکنید.

## نصب روی cPanel

1. فایل‌های پروژه را در پوشه‌ای از حساب هاست (ترجیحاً خارج از `public_html`) بارگذاری و استخراج کنید.
2. در **cPanel → Setup Node.js App** یک برنامه بسازید و Node.js 18 یا جدیدتر، مسیر ریشه پروژه و فایل شروع `server.js` را انتخاب کنید.
3. از **Run NPM Install** در cPanel یا Terminal دستور زیر را اجرا کنید:
   ```bash
   npm install
   ```
4. برنامه را راه‌اندازی/Restart کنید. برنامه روی `0.0.0.0` و پورتی که cPanel در `PORT` می‌دهد گوش می‌کند.
5. نشانی دامنه به‌همراه `/install` را باز کنید و ویزارد سه‌مرحله‌ای را کامل کنید:
   - مشخصات مدرسه؛
   - انتخاب ذخیره‌سازی JSON یا MySQL؛
   - ساخت حساب مدیر با شمارهٔ موبایل معتبر و گذرواژه قوی.
6. پس از پایان نصب، از صفحه اصلی وارد پنل شوید. ویزارد نصب برای سامانه نصب‌شده قفل می‌شود.

### انتخاب پایگاه داده

- **فایل محلی JSON:** راه‌اندازی بدون تنظیمات دیتابیس؛ اطلاعات در `data/state.json` با مجوز خصوصی `0600` و به‌روزرسانی‌ها به‌صورت اتمیک ذخیره می‌شوند؛ مجوز فایل قدیمی نیز هنگام راه‌اندازی دوباره محدود می‌شود. برای دمو، توسعه و مدرسه‌های کوچک مناسب است. از این فایل نسخه پشتیبان بگیرید.
- **MySQL/MariaDB:** ابتدا در cPanel یک Database و Database User بسازید، کاربر را با دسترسی کامل به همان دیتابیس متصل کنید و سپس اطلاعات را در ویزارد وارد کنید. اتصال قبل از نصب بررسی می‌شود. برنامه ساختار جدول‌ها را ایجاد می‌کند؛ خود دیتابیس باید از قبل در cPanel ساخته شده باشد. تنظیمات اتصال در `data/config.json` با دسترسی محدود ذخیره می‌شود؛ این فایل در Git نادیده گرفته شده است.

### ورود با پیامک IPPanel

1. شمارهٔ موبایل مدیر در مرحلهٔ سوم ویزارد نصب دریافت و روی حساب او ذخیره می‌شود؛ شمارهٔ حساب‌های دیگر را از بخش «کاربران» ثبت کنید. شماره‌های ایران با قالب محلی `۰۹۱۲…` یا بین‌المللی پذیرفته و پیش از تطبیق به E.164 نرمال می‌شوند.
2. در پنل IPPanel یک API Key برای Edge API بسازید و یک الگوی پیامکی فعال/تأییدشده آماده کنید. شناسهٔ pattern و نام متغیر داخل الگو (به‌طور پیش‌فرض `code`) را در تنظیمات مدرسه وارد کنید؛ متغیر باید دقیقاً با نام پارامتر الگو یکی باشد.
3. از تنظیمات مدیر، «هر دو روش» یا «فقط کد پیامکی» را انتخاب و کلید API، شمارهٔ فرستنده با قالب E.164، شناسهٔ الگو و نام متغیر را ذخیره کنید. ورود پیامکی برای مدیر، معلم، دانش‌آموز، ولی و نقش‌های سفارشی یکسان کار می‌کند. فعال‌سازی بدون تنظیم کامل IPPanel و دست‌کم یک شمارهٔ فعال و یکتا پذیرفته نمی‌شود.

کلید API در مرورگر بازگردانده نمی‌شود و در `data/config.json` خصوصی با مجوز `0600` ذخیره می‌شود؛ مسیر داده را خارج از `public_html` نگه دارید. در صورت مدیریت اعتبارنامه با محیط سرور، از `IPPANEL_API_KEY`، `IPPANEL_FROM_NUMBER`، `IPPANEL_PATTERN_CODE` و `IPPANEL_OTP_PARAM` استفاده کنید. کد الگوی IPPanel باید از پیش در حساب ارائه‌دهنده ساخته شده باشد؛ برنامه OTP را تولید می‌کند و برای ارسال از Edge pattern endpoint استفاده می‌کند.

در نصب واقعی و روی هاست عمومی، از حسابی که ویزارد ساخته استفاده کنید؛ حساب‌های نمونه فقط در اجرای نمایشی ساخته می‌شوند. سرور Node را با `NODE_ENV=production` اجرا کنید و از انتشار پوشه `data` به‌عنوان فایل استاتیک خودداری کنید.

## قابلیت‌های نسخهٔ ۱.۳.۰

سامانه از **۲۵ ماژول مستقل** تشکیل شده است. مدیر می‌تواند از «مدیریت ماژول‌ها» قابلیت‌های غیرضروری را خاموش و هر زمان دوباره فعال کند. داشبورد، پرونده دانش‌آموز، معلم و کلاس‌ها و بخش تنظیمات/مدیریت ماژول‌ها زیربنایی هستند و خاموش نمی‌شوند تا فرم‌ها و ارتباط داده‌های مدرسه از کار نیفتند. دارایی‌های اصلی رابط نیز با شناسهٔ نسخه cache-bust می‌شوند تا استقرار جدید فایل‌های قدیمی مرورگر را نگه ندارد.

1. داشبورد مدیریتی و شاخص‌های روزانه؛
2. پرونده کامل دانش‌آموز و اطلاعات تماس ولی/اضطراری؛
3. مدیریت معلم و تخصص آموزشی؛
4. مدیریت کلاس، ظرفیت، اتاق و تعیین معلم مسئول؛
5. پرونده و راه‌های تماس اولیا؛
6. حضور و غیاب روزانه، تأخیر، غیبت و مرخصی؛
7. درس‌ها و ساعات هفتگی؛
8. برنامهٔ هفتگی چندزنگی با تنظیم مرکزی روزهای مدرسه و ساعت‌های نوبت صبح/عصر، دبیر جداگانه برای هر جلسه، سال تحصیلی مستقل و فیلتر کلاس/دبیر/روز/سال برای نقش‌های مرتبط؛
9. تکالیف و مهلت تحویل؛
10. برنامه آزمون‌ها؛
11. ثبت نمره و مشاهده کارنامه؛
12. تیکت گفت‌وگو بین مدرسه، معلم، دانش‌آموز و ولی؛
13. اطلاعیه‌های مدرسه؛
14. تقویم ماهانه مدرسه، جلسه‌ها و اردوها؛ نمایش برنامه روزانه کلاس‌ها با فیلتر پایه و ساعت هر زنگ؛
15. سوابق پیام‌رسانی؛
16. شهریه، اقساط و وضعیت پرداخت؛
17. فهرست و موجودی کتابخانه؛
18. مسیرهای سرویس مدرسه؛
19. اسناد و فایل‌های مدرسه؛
20. گزارش‌های مدیریتی؛
21. حساب‌های کاربران با نقش مدیر/معلم/دانش‌آموز/ولی؛
22. نقش‌ها و سطوح دسترسی؛
23. گزارش تغییرات و فعالیت کاربران؛
24. تنظیمات و مشخصات مدرسه؛
25. روشن/خاموش کردن ماژول‌ها.

فرم ساخت دانش‌آموز یا معلم می‌تواند هم‌زمان حساب پنل مربوطه را نیز ایجاد کند. دسترسی هر حساب بر اساس نقش محدود است؛ معلم داده کلاس خودش را می‌بیند و دانش‌آموز/ولی به پرونده مرتبط با خود دسترسی دارند. تیکت‌ها تاریخچه پیام دارند و مدیر می‌تواند آن‌ها را ببندد.

### تغییرات نسخهٔ ۱.۳.۰

- **تقویم هفتگی قابل تنظیم:** مدیر در تنظیمات، روزهای آموزشی و تا ۱۶ زنگ با نام، نوبت و ساعت شروع/پایان را تعریف می‌کند؛ اعتبارسنجی سرور از شناسهٔ تکراری، ساعت وارونه و هم‌پوشانی در نوبت مشترک جلوگیری می‌کند. تغییر زمان یک زنگ برنامه‌های وابسته را همگام می‌کند و تغییر ناسازگار ذخیره نمی‌شود.
- **جلسه‌های مستقل و چندگانه:** هر ردیف برنامه یک جلسهٔ جدا با کلاس، درس، زنگ، دبیر، اتاق و سال تحصیلی است؛ پس یک کلاس می‌تواند در روز چند درس و دبیر متفاوت داشته باشد. برنامه‌ها در سال‌های تحصیلی متفاوت با هم تداخل کاذب ندارند.
- **نمایش نقش‌محور و فیلتر:** فهرست برنامه براساس روز، کلاس، دبیر و سال تحصیلی فیلتر و بر پایهٔ ساعت مرتب می‌شود. دبیر فقط برنامهٔ کلاس‌های مرتبط، و دانش‌آموز/ولی فقط برنامهٔ کلاس خود را می‌بیند؛ نام دبیر برای نمایش برنامه ارائه می‌شود، نه پروندهٔ کامل او.
- **سازگاری داده‌های قبلی:** هنگام راه‌اندازی، تنظیمات پیش‌فرض و شناسهٔ زنگ برای برنامه‌های قدیمی با زمان‌های منطبق بازسازی می‌شود؛ ارجاع‌های برنامه نیز هنگام حذف کلاس/درس/دبیر حفظ می‌شوند.
- **ممیزی یکپارچگی و امنیت:** فیلدهای عددی و مقادیر وضعیت در سمت سرور اعتبارسنجی می‌شوند؛ ورودی عددی رقم فارسی/عربی را می‌پذیرد، شمارندهٔ کسری/منفی و حداکثر نمرهٔ صفر رد می‌شود و ورودی خالی در داده ذخیره نمی‌شود. صفحه‌بندی API نیز صحیح و در محدودهٔ نتیجه محدود می‌شود. کلاس تازه شمارش دستی دانش‌آموز نمی‌پذیرد و ثبت‌نام در کلاس غیرفعال مسدود است. تغییر پیوند پروندهٔ ولی/دانش‌آموز، نشست‌ها و چالش‌های OTP حساب قبلی را لغو می‌کند؛ حساب متصل به پروندهٔ غیرفعال نیز نمی‌تواند فعالانه وارد شود. ورود گذرواژه علاوه بر سقف ۷ تلاش برای هر IP/نام کاربری، سقف ۶۰ شکست برای هر IP در ۱۵ دقیقه و `Retry-After` دارد؛ نقشهٔ تلاش‌ها سقف دارد و نشست‌های منقضی پاک می‌شوند و تعداد نشست‌های درون‌حافظه‌ای به ۱۰٬۰۰۰ محدود است. سرآیندهای IP و HTTPS فقط از اتصال مستقیم TLS یا پراکسی مورداعتماد پذیرفته می‌شوند. فایل‌های رابط نیز CSP هم‌مبدأ با allowlist امن برای iframeهای Arena preview، `nosniff` و محدودیت قابلیت‌های مرورگر دارند؛ handler جاوااسکریپت درون‌خطی حذف شده است.
- **حضور و داده‌های قدیمی:** اصلاح حضور در روزهای گذشته ساعت همان رکورد را حفظ می‌کند؛ برنامه‌های قدیمی بدون شناسهٔ درس از روی درس/پایه مهاجرت می‌شوند و سال‌های معادل فارسی/لاتین در گزینه‌ها تکرار نمی‌شوند.
- **انتشار کنترل‌شده:** اطلاعیه‌های پیش‌نویس یا زمان‌بندی‌شده برای نقش‌های غیرمدیر مخفی‌اند؛ مخاطب پایه به پرونده‌های مرتبط محدود می‌شود.
- **پایش ذخیره‌ساز:** `GET /api/health` فقط وضعیت عمومی را برمی‌گرداند؛ سلامت JSON و اجرای `SELECT 1` برای MySQL در سرور بررسی می‌شود و خطای ذخیره‌ساز پاسخ ۵۰۳ می‌دهد.

### تغییرات نسخهٔ ۱.۲.۰

- **سه سیاست ورود برای همهٔ نقش‌ها:** مدیر می‌تواند نام کاربری/گذرواژه، فقط OTP تلفنی یا هر دو (تب انتخابی در صفحهٔ ورود) را تعیین کند. شمارهٔ موبایل مدیر در مرحلهٔ سوم ویزارد اجباری است و روی حساب او ذخیره می‌شود؛ شمارهٔ حساب‌های دیگر از بخش کاربران قابل ثبت است. هر شماره باید به تنها یک حساب فعال وصل باشد.
- **ارسال واقعی OTP با IPPanel Edge:** کد شش‌رقمی با الگوی IPPanel ارسال می‌شود؛ کلید در سرور می‌ماند و درخواست به endpoint رسمی pattern می‌رود. درخواست ارائه‌دهنده timeout ده‌ثانیه‌ای دارد و خطا یا کلید خام به کاربر نهایی بازگردانده نمی‌شود.
- **پنج محافظ امنیتی OTP:** (۱) نرمال‌سازی ارقام فارسی/عربی و شماره‌ها به E.164 و ردّ نگاشت‌های تکراری؛ (۲) محدودیت هم‌زمان بر اساس IP/شماره شامل مکث ۶۰ثانیه‌ای و سقف‌های ۳ درخواست برای IP+شماره، ۵ برای شماره و ۶۰ برای IP در ۱۵ دقیقه؛ (۳) پاسخ یکسان برای شمارهٔ موجود/ناموجود و ارسال غیرهم‌زمان برای کاهش نشت وجود حساب؛ (۴) نگهداری HMAC-SHA256 به‌جای کد خام، انقضای ۵دقیقه‌ای، حداکثر ۵ تلاش و مصرف یک‌بارهٔ چالش؛ (۵) نگهداری کلید در فایل خصوصی `0600` یا متغیر محیطی، عدم بازگشت کلید در API و timeout/خطای عمومی برای سرویس پیامک.

برای اینکه محدودیت IP پشت cPanel/Passenger برای هر مراجعه‌کننده جدا بماند، وقتی اتصال Node از loopback می‌آید، سرور از آخرین IP معتبر `X-Forwarded-For` استفاده می‌کند. برای reverse proxy دیگری فقط در صورت اعتماد به آن، `TRUST_PROXY=1` را تنظیم کنید؛ هدر ارسالی کاربر را بدون proxy مورداعتماد نپذیرید.

- **قفل نصب پس از راه‌اندازی:** پیوند نصب/راهنما از صفحهٔ ورود و پنل حذف شده و `/install`، `/install/` و `/install.html` پس از نصب از سمت سرور 404 می‌دهند؛ endpointهای نصب نیز نصب مجدد را رد می‌کنند.
- **سخت‌سازی پیکربندی و بازیابی:** فعال‌سازی حالت تلفنی به پیکربندی کامل provider و شمارهٔ یکتای مدیر فعال نیاز دارد؛ restore پشتیبانِ دارای ورود تلفنی بدون IPPanel و شمارهٔ یکتای مدیر رد می‌شود. تنظیمات SMS داخل پشتیبان داده قرار نمی‌گیرند.

### تغییرات نسخهٔ ۱.۱.۰

- **ثبت سریع حضور معلم:** کلاس و تاریخ را انتخاب کنید؛ همهٔ دانش‌آموزان فعال فهرست می‌شوند و پیش‌فرض حضور است. معلم فقط غایبان را با سوئیچر مشخص می‌کند. ذخیرهٔ دوباره همان رکوردهای همان روز را اصلاح می‌کند و رکورد تکراری نمی‌سازد. کنترل کلاس‌های مجاز و فهرست شناسه‌های ارسالی در سمت سرور انجام می‌شود.
- **برنامهٔ هفتگی بدون هم‌پوشانی:** بازه‌های ساعت فارسی/لاتین و روز هفته عادی‌سازی می‌شوند؛ هم‌زمانی یک کلاس، معلم یا اتاق برای دو زنگ رد می‌شود. برنامهٔ نمونه نیز ممیزی شده تا تداخل اولیه نداشته باشد.
- **تاریخ/منطقهٔ زمانی:** منطقهٔ زمانی IANA مدرسه در تنظیمات تعیین می‌شود و برای تاریخ امروز، ساعت ثبت و نمودار هفتگی به کار می‌رود. تاریخ‌های تقویمی فقط با جابه‌جایی timezone به روز دیگری منتقل نمی‌شوند.
- **انتخاب‌گرهای بزرگ:** گزینه‌های فرم از API به‌صورت صفحه‌بندی‌شده بارگیری می‌شوند؛ انتخاب پرونده بین بیش از ۱۰۰ رکورد نیز محدود به صفحهٔ اول نیست.
- **پشتیبان و بازیابی:** از بخش تنظیمات مدیر می‌تواند پشتیبان بسازد/دانلود کند یا فایل JSON را بازیابی کند. فایل‌ها در پوشهٔ دادهٔ خصوصی با مجوز محدود نگهداری می‌شوند؛ پشتیبان شامل هش گذرواژه‌هاست و باید محرمانه بماند. بازیابی به نقش مدیر و گذرواژهٔ فعلی نیاز دارد، قالب/ساختار را اعتبارسنجی می‌کند، پیش از جایگزینی پشتیبان ایمنی می‌سازد و نشست‌ها را می‌بندد. نسخهٔ خودکار هنگام راه‌اندازی و سپس هر ۲۴ ساعت ساخته می‌شود و ۱۴ نسخهٔ اخیر باقی می‌ماند. این سازوکار جای نسخهٔ جداگانهٔ خارج از هاست را نمی‌گیرد.
- **نقش‌ها و دسترسی:** دسترسی ماژول، مشاهده و نوشتن نقش‌های معلم/دانش‌آموز/ولی قابل تنظیم است. مدیر می‌تواند نقش سفارشی (مثلاً معاون یا حسابدار) بسازد؛ ماژول‌ها و دسترسی داده را صریحاً انتخاب کند و نقش را به کل مدرسه یا کلاس‌های مشخص محدود کند. مسیرهای مدیر، کاربران، گزارش فعالیت، تنظیمات و مدیریت ماژول‌ها به نقش سفارشی واگذار نمی‌شوند. نقش دارای حساب کاربری تا زمان انتقال حساب‌ها حذف نمی‌شود.

ورود OTP در نسخهٔ ۱.۲.۰ پیامک واقعی را از طریق IPPanel Edge API می‌فرستد و به API Key و pattern فعال نیاز دارد. بخش «سوابق پیام‌رسانی» برای اطلاعیه‌های عمومی همچنان داخلی است؛ درگاه پرداخت و سرویس‌های ابری در این نسخه متصل نیستند و ثبت مالی به‌تنهایی تراکنش بانکی انجام نمی‌دهد.

## ساختار پروژه (MVC/لایه‌ای)

```text
server.js                         # نقطه ورود، HTTP server و سرو فایل‌ها
src/config.js                     # خواندن تنظیمات امن و متغیرهای محیطی
src/controllers/apiController.js  # کنترلر احراز هویت، نصب و API ماژول‌ها
src/models/store.js               # مدل ذخیره‌سازی JSON با نوشتن اتمیک
src/models/mysqlStore.js          # مدل MySQL/MariaDB
src/data/modules.js               # تعریف ماژول‌ها و دسترسی نقش‌ها
src/data/seed.js                  # راه‌اندازی داده‌های اولیه و کاربران دمو
src/lib/security.js               # هش گذرواژه و ابزارهای امنیتی
src/lib/dates.js                  # تاریخ مدرسه، timezone و اعتبارسنجی ISO
src/lib/backupManager.js          # پشتیبان‌گیری، اعتبارسنجی restore و نگهداری امن
public/                            # رابط فارسی RTL، CSS و JavaScript
public/fonts/                      # فایل‌های WOFF2 فونت Vazirmatn و مجوز OFL
data/seed.json                     # داده‌های نمونه غیرحساس
```

در MySQL، رکوردها در جدول دارای کلید مرکب «مجموعه/شناسه» و payload از نوع JSON ذخیره می‌شوند؛ تغییرات فقط برای رکوردهای تغییریافته نوشته می‌شوند. نسخه فعلی برای یک مدرسه و اجرای تک‌نمونه‌ای Node طراحی شده است؛ برای استقرار چندنمونه‌ای/ترافیک بالا، مرحله بعدی باید نشست اشتراکی (مثلاً Redis) و گزارش‌گیری/صفحه‌بندی مستقیم SQL را اضافه کند.

## تنظیمات و آزمون

- متغیرهای محیطی دیتابیس: `DB_DRIVER=mysql`، `DB_HOST`، `DB_PORT`، `DB_NAME`، `DB_USER`، `DB_PASSWORD`.
- مسیر داده قابل تغییر است: `DATA_DIR=/path/to/private-data`.
- بررسی نحو فایل‌ها و اجرای آزمون‌های یکپارچگی API برای دسترسی نقش‌های پیش‌فرض/سفارشی، محدودهٔ کلاس، حضور گروهی، تداخل برنامه، پشتیبان/بازیابی، timezone، OTP/IPPanel، قفل نصب، پایش سلامت ذخیره‌ساز و یکپارچگی داده (در حال حاضر ۴۷ آزمون):
  ```bash
  npm run check
  npm test
  ```
- فایل‌های `data/state.json`، `data/config.json` و پوشهٔ `data/backups/` را به وب‌سرور استاتیک معرفی نکنید. در محیط تولید حالت دمو را خاموش نگه دارید، HTTPS را فعال کنید و پشتیبان قابل‌بازیابی را جدا از هاست نیز نگهداری کنید.
- فایل `data/seed.json` داده‌های نمونه دانش‌آموز، معلم، کلاس، حضور و غیاب، تیکت، تکلیف، نمره، شهریه، اطلاعیه و ... را شامل می‌شود. در ویزارد می‌توان حفظ یا پاک‌سازی این داده‌های نمایشی را انتخاب کرد.

## APIهای اصلی

- احراز هویت: `GET /api/auth/options`، `POST /api/auth/login`، `POST /api/auth/otp/request`، `POST /api/auth/otp/verify`، `/api/auth/me` و `/api/auth/logout`؛ `/api/install` فقط پیش از نصب قابل استفاده است؛
- تنظیم ورود و provider پیامک توسط مدیر: `GET` و `PATCH /api/settings`؛
- داده‌های ماژول‌ها: `/api/records/:module` با فیلتر و صفحه‌بندی؛
- حضور سریع: `GET` و `POST /api/attendance/class/:classId`؛ بدنهٔ ذخیره `{ "date": "YYYY-MM-DD", "absentIds": ["student-id"] }`؛
- دسترسی: `GET /api/records/roles` و مسیرهای مدیر `POST /api/roles`، `PATCH /api/roles/:id` و `DELETE /api/roles/:id`؛
- تنظیمات و ماژول‌ها: `/api/settings` و `/api/modules/:id`؛
- نسخهٔ پشتیبان مدیر: `/api/admin/backups`، `/api/admin/backups/:filename` و `POST /api/admin/restore`.

تمام مسیرهای مدیریت به نشست معتبر و مجوز نقش در سمت سرور وابسته‌اند؛ پنهان‌کردن منو به‌تنهایی مرز امنیتی محسوب نمی‌شود.
