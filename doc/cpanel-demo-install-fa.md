# راهنمای نصب نسخهٔ نمایشی مدرسه‌یار روی cPanel

این راهنما یک **نمونهٔ جدا و قابل‌آزمایش** روی cPanel می‌سازد؛ نه مدرسهٔ عملیاتی. برنامه با داده‌های نمونه و حساب‌های نمایشی بالا می‌آید و ویزارد نصب برای آن فعال نیست.

> **هشدار امنیتی مهم:** حالت دمو برای نمایش عمومیِ بدون محافظ طراحی نشده است. صفحهٔ ورود حساب‌های یک‌کلیکی را نشان می‌دهد و در حالت `DEMO_MODE=1` دسترسی نمایشی ساده‌تر است؛ هرکسی که به نشانی برسد می‌تواند وارد نقش‌های نمونه شود و داده‌های دمو را تغییر دهد. نسخهٔ دمو را بدون یک لایهٔ دسترسی بیرونیِ آزمایش‌شده روی اینترنت عمومی نگذارید. هیچ اطلاعات واقعی مدرسه یا دانش‌آموز را وارد نکنید.

## تفاوت دمو با نصب عملیاتی

| نسخهٔ دمو | نسخهٔ عملیاتی |
|---|---|
| `DEMO_MODE=1` فقط در برنامهٔ جداگانهٔ دمو | `DEMO_MODE` تعریف نمی‌شود |
| دادهٔ نمونه و حساب‌های ازپیش‌ساخته‌شده | ویزارد نصب و حساب مدیر مخصوص مدرسه |
| پایگاه JSON و پوشهٔ دادهٔ مستقل | JSON یا MySQL طبق انتخاب مدرسه |
| ویزارد `/install` غیرفعال است | نصب نخست از `/install` انجام می‌شود |

**هرگز** حالت دمو را روی Application عملیاتی فعال نکنید؛ پوشهٔ داده، دیتابیس، دامنه و Application دمو باید از تولید جدا باشند.

## ۱) آماده‌سازی دامنه و محافظ دسترسی

1. یک زیردامنهٔ جدا بسازید؛ برای نمونه `demo.example.com`.
2. گواهی HTTPS آن را فعال کنید.
3. در cPanel از **Directory Privacy** یا ابزار محافظت دسترسی هاست استفاده کنید؛ در صورت نیاز از IP Allowlist یا Basic Auth در لایهٔ وب‌سرور/پراکسی بهره بگیرید.
4. مطمئن شوید محافظ دسترسی **کل زیردامنه، از جمله مسیرهای `/api`** را پوشش می‌دهد. در پنجرهٔ خصوصی مرورگر نشانی ریشه و `/api/health` را آزمایش کنید. اگر API بدون گذرواژه در دسترس است، دمو را برای دیگران منتشر نکنید و از پشتیبانی هاست بخواهید محافظت سراسری را تنظیم کند.

فقط پنهان‌کردن لینک، انتخاب URL سخت‌حدس یا گذاشتن رمز در صفحهٔ معرفی کافی نیست؛ حساب‌های نمایشی عمومی و از قبل شناخته‌شده‌اند.

## ۲) دریافت کد دمو

برای دمو نیز ریشهٔ برنامه را بیرون از `public_html` قرار دهید و یک کپی مستقل بسازید؛ مثلاً:

```text
/home/CPANEL_USER/apps/madresehyar-demo
```

در snapshot فعلی این راهنما، نسخهٔ کامل پروژه در شاخهٔ `arena/01a0f7fc-mad` قرار دارد. اگر نسخه بعداً به شاخهٔ انتشار دیگری منتقل شد، شاخهٔ تأییدشدهٔ همان نسخه را انتخاب کنید. نمونهٔ دریافت با Terminal:

```bash
mkdir -p "$HOME/apps"
git clone --depth 1 --branch arena/01a0f7fc-mad \
  https://github.com/diswebir/mad.git "$HOME/apps/madresehyar-demo"
```

یا ZIP همان شاخه را در Application Root استخراج کنید. فایل `server.js` باید مستقیماً در ریشهٔ برنامه باشد. `node_modules` را بارگذاری نکنید.

## ۳) ساخت مسیر دادهٔ مستقل دمو

برای اینکه دمو به هیچ دادهٔ مدرسهٔ واقعی وصل نشود، یک مسیر کاملاً جدا بسازید:

```bash
mkdir -p "$HOME/private/madresehyar-demo-data"
chmod 700 "$HOME/private/madresehyar-demo-data"
```

مسیر واقعی Home را با `echo "$HOME"` پیدا کنید. مسیر `DATA_DIR` را داخل `public_html` نگذارید و مسیر `DATA_DIR` برنامهٔ عملیاتی را برای دمو استفاده نکنید.

## ۴) ایجاد Node.js App دمو

1. در cPanel وارد **Setup Node.js App → Create Application** شوید.
2. یک نسخهٔ LTS پشتیبانی‌شدهٔ Node انتخاب کنید؛ حداقل موردنیاز پروژه `18.17` است.
3. **Application mode** را روی `Production` بگذارید؛ این گزینه با حالت محصول دمو فرق دارد.
4. **Application root** را روی `apps/madresehyar-demo` و **Application URL** را روی ریشهٔ `demo.example.com` تنظیم کنید. برنامه را زیرمسیر دامنه نصب نکنید.
5. **Application startup file** را `server.js` وارد کنید.
6. فقط متغیرهای زیر را در Environment Variables همین برنامهٔ دمو ثبت کنید:

   | نام | مقدار |
   |---|---|
   | `NODE_ENV` | `production` |
   | `DEMO_MODE` | `1` |
   | `DATA_DIR` | مسیر مطلق و جدا؛ نمونه: `/home/CPANEL_USER/private/madresehyar-demo-data` |

   `DEMO_MODE=1` را فقط روی این Node.js App بگذارید. در cPanel نیازی به اجرای `npm run dev` نیست؛ Startup file همان `server.js` می‌ماند. این پروژه `.env` را خودکار نمی‌خواند.

7. متغیرهای `DB_DRIVER`، `DB_HOST`، `DB_NAME`، `DB_USER`، `DB_PASSWORD` و تنظیمات IPPanel را برای دمو تعریف نکنید. دمو باید با JSON محلی و دادهٔ نمونه اجرا شود.
8. روی **Run NPM Install** بزنید؛ یا در محیط Node همان Application و در ریشهٔ پروژه اجرا کنید:

   ```bash
   npm ci --omit=dev
   ```

9. برنامه را Start/Restart کنید و لاگ‌های cPanel را بررسی کنید. cPanel پورت `PORT` را تعیین می‌کند؛ پورت را در کد ثابت نکنید.

## ۵) بازکردن دمو و حساب‌های نمونه

در حالی که محافظ دسترسی فعال است، نشانی HTTPS زیردامنه را باز کنید:

```text
https://demo.example.com/
```

در شروع، داده‌های نمونه از `data/seed.json` ساخته می‌شوند؛ ویزارد نصب لازم نیست و `/install` عمداً در حالت دمو 404 می‌دهد. صفحه ممکن است دکمهٔ ورود یک‌کلیکی داشته باشد؛ در صورت نیاز می‌توانید اطلاعات زیر را هم وارد کنید:

| نقش | نام کاربری | گذرواژه |
|---|---|---|
| مدیر مدرسه | `admin` | `admin123` |
| معلم | `ahmadi` | `teacher123` |
| دانش‌آموز | `sara` | `student123` |
| ولی دانش‌آموز | `maryam` | `parent123` |

این گذرواژه‌ها محرمانه نیستند و برای محافظت از دمو محسوب نمی‌شوند. داده‌ها نمونه‌اند و ممکن است با فعالیت بازدیدکنندگان تغییر کنند. دمو را به IPPanel، SMS واقعی، پایگاه عملیاتی یا دادهٔ حقیقی مدرسه وصل نکنید.

برای بررسی سلامت سرویس، نشانی زیر باید پاسخ `{"status":"ok"}` بدهد (اگر محافظ دسترسی فعال است، ابتدا از آن عبور کنید):

```text
https://demo.example.com/api/health
```

## ۶) بازنشانی داده‌های دمو

فعالیت کاربران دمو ممکن است در فایل وضعیت ذخیره شود و با Restart از بین نرود. برای بازگرداندن دادهٔ اولیه:

1. در cPanel برنامهٔ دمو را **Stop** کنید.
2. مقدار `DATA_DIR` را بررسی کنید؛ باید مسیر خصوصی و مخصوص همین دمو باشد و با مسیر هیچ سامانهٔ عملیاتی یکی نباشد.
3. یک مسیر **جدید و خالی** بسازید، مثلاً `/home/CPANEL_USER/private/madresehyar-demo-data-reset-new`، و مجوز پوشه را به کاربر Node بدهید.
4. مقدار `DATA_DIR` را فقط در Node.js App دمو به مسیر جدید تغییر دهید و برنامه را Restart کنید.
5. پس از اطمینان از بالا آمدن نمونهٔ تازه، مسیر قدیمی را نگه دارید تا اگر داده‌ای لازم بود قابل بازیابی باشد؛ فایل‌های کد یا `data/seed.json` را حذف نکنید.

- [ ] `DEMO_MODE=1` فقط روی Application دمو است.
- [ ] ریشهٔ کد و `DATA_DIR` دمو با تولید جدا هستند.
- [ ] دیتابیس/شمارهٔ تلفن/API Key/اطلاعات واقعی مدرسه در دمو وارد نشده است.
- [ ] محافظ بیرونی، صفحه و مسیرهای API را در مرورگر خصوصی پوشش می‌دهد.
- [ ] می‌دانید حساب‌های جدول بالا عمومی‌اند و داده‌های دمو قابل تغییر هستند.
