# راهنمای نصب نسخهٔ عملیاتی مدرسه‌یار روی cPanel

این راهنما برای راه‌اندازی نسخهٔ واقعی سامانه روی هاست است؛ نه نسخهٔ نمایشی. نام بعضی گزینه‌ها در cPanel شرکت‌های مختلف کمی فرق دارد. اگر گزینهٔ **Setup Node.js App** یا اجرای Node.js در هاست شما وجود ندارد، از پشتیبانی هاست بخواهید Node.js و Passenger/cPanel Application Manager را فعال کند.

> **مهم:** برای نسخهٔ عملیاتی `DEMO_MODE=1` را تنظیم نکنید و `npm run dev` را اجرا نکنید. حساب‌های دمو عمومی و داده‌های آن‌ها نمونه هستند.

## ۱) پیش‌نیازها و انتخاب دامنه

- هاست cPanel با امکان اجرای Node.js؛ نسخهٔ انتخابی Node باید حداقل `18.17` باشد. در صورت امکان، یک نسخهٔ LTS پشتیبانی‌شده و جدیدتر را انتخاب کنید.
- یک دامنه یا زیردامنه که به هاست متصل است؛ نمونه: `school.example.com`.
- دسترسی به **Setup Node.js App** و ترجیحاً **Terminal** یا **Git Version Control**.
- گواهی HTTPS فعال. برای ورود مدیر و داده‌های مدرسه، از HTTP استفاده نکنید.

برنامه را روی ریشهٔ دامنه/زیردامنه متصل کنید؛ برای نمونه `https://school.example.com/`. رابط و API از مسیرهای ریشه‌دار مثل `/api` استفاده می‌کنند، پس نصب در زیرمسیرهایی مثل `example.com/mad` ممکن است مسیر فایل‌ها را بشکند.

## ۲) دریافت فایل‌های سامانه

**ریشهٔ برنامه را بیرون از `public_html` نگه دارید.** برای نمونه:

```text
/home/CPANEL_USER/apps/madresehyar
```

فایل‌ها را با Git Version Control، Terminal یا ZIP در همین پوشه قرار دهید. هنگام استخراج ZIP، مطمئن شوید `server.js`، `package.json` و پوشه‌های `public` و `src` مستقیماً در ریشهٔ برنامه باشند؛ نه داخل یک پوشهٔ تو‌در‌تو. `node_modules` را بارگذاری نکنید؛ در cPanel نصب خواهد شد.

### دریافت از GitHub

در snapshot فعلی این راهنما، نسخهٔ کامل پروژه در شاخهٔ `arena/01a0f7fc-mad` قرار دارد. اگر بعداً نسخه به شاخهٔ انتشار دیگری منتقل شد، همان شاخهٔ تأییدشده را انتخاب کنید. در صورت داشتن Terminal و دسترسی Git:

```bash
mkdir -p "$HOME/apps"
git clone --depth 1 --branch arena/01a0f7fc-mad \
  https://github.com/diswebir/mad.git "$HOME/apps/madresehyar"
```

اگر با ZIP نصب می‌کنید، ZIP همان شاخهٔ موردنظر را از GitHub بگیرید و محتوایش را در Application Root استخراج کنید.

## ۳) ساخت پوشهٔ خصوصی داده‌ها

پوشهٔ داده را خارج از `public_html` و جدا از فایل‌های قابل‌دسترسی وب بسازید. در cPanel Terminal:

```bash
mkdir -p "$HOME/private/madresehyar-data"
chmod 700 "$HOME/private/madresehyar-data"
```

در مثال‌های این راهنما، `CPANEL_USER` را با نام حساب cPanel خود جایگزین کنید. مسیر واقعی Home را می‌توانید با `echo "$HOME"` ببینید. برنامه فایل‌های وضعیت، تنظیمات اتصال و پشتیبان‌ها را در `DATA_DIR` نگه می‌دارد.

## ۴) ساخت برنامه در Setup Node.js App

1. در cPanel وارد **Setup Node.js App** شوید و **Create Application** را انتخاب کنید.
2. نسخهٔ Node را انتخاب کنید (حداقل `18.17`؛ ترجیحاً LTS پشتیبانی‌شدهٔ جدیدتر).
3. **Application mode** را روی `Production` بگذارید.
4. **Application root** را روی مسیر پروژه تنظیم کنید؛ برای مثال `apps/madresehyar`.
5. **Application URL** را روی دامنه/زیردامنه و ریشهٔ آن بگذارید.
6. **Application startup file** را `server.js` وارد کنید.
7. متغیرهای محیطی زیر را در صفحهٔ همان برنامه اضافه کنید:

   | نام | مقدار نمونه | توضیح |
   |---|---|---|
   | `NODE_ENV` | `production` | برای اجرای عملیاتی |
   | `DATA_DIR` | `/home/CPANEL_USER/private/madresehyar-data` | مسیر خصوصی داده‌ها؛ مقدار را با مسیر واقعی خود عوض کنید |

   `DEMO_MODE` را تعریف نکنید (یا اگر قبلاً اضافه شده، حذفش کنید). فایل `.env` به‌تنهایی توسط برنامه خوانده نمی‌شود؛ متغیرها را در تنظیمات محیطی برنامهٔ cPanel وارد کنید.

8. برنامه را ایجاد کنید. cPanel معمولاً پورت `PORT` را خودش تعیین می‌کند؛ آن را در کد یا فایل تنظیمات ثابت نکنید.
9. در صفحهٔ برنامه **Run NPM Install** را بزنید. اگر از Terminal استفاده می‌کنید، ابتدا محیط Node معرفی‌شده در صفحهٔ cPanel را فعال کنید، سپس در ریشهٔ برنامه اجرا کنید:

   ```bash
   npm ci --omit=dev
   ```

10. برنامه را **Start/Restart** کنید و خطاهای بخش Logs را بررسی کنید.

## ۵) انتخاب ذخیره‌سازی

در ویزارد می‌توانید JSON یا MySQL/MariaDB را انتخاب کنید.

### گزینهٔ الف: JSON

برای شروع ساده به ساخت دیتابیس نیاز ندارد. وضعیت در `DATA_DIR/state.json` نوشته می‌شود. از این مسیر نسخهٔ پشتیبان منظم داشته باشید. این نسخه برای یک مدرسه و اجرای تک‌نمونه‌ای Node طراحی شده است؛ چند پردازه یا چند Application را هم‌زمان به یک فایل JSON وصل نکنید.

### گزینهٔ ب: MySQL/MariaDB

1. در cPanel، بخش **MySQL Databases** یا **MySQL Database Wizard** را باز کنید.
2. دیتابیس و کاربر بسازید و کاربر را با **ALL PRIVILEGES** به همان دیتابیس اضافه کنید.
3. نام کامل دیتابیس و کاربر را یادداشت کنید؛ cPanel معمولاً پیشوند نام حساب را اضافه می‌کند.
4. در ویزارد مدرسه‌یار گزینهٔ MySQL را انتخاب کنید، اطلاعات را وارد و **بررسی اتصال** را اجرا کنید. میزبان غالباً `localhost` و پورت معمولاً `3306` است؛ مقدار قطعی را از هاست بپرسید.
5. ویزارد جدول‌های لازم را ایجاد می‌کند؛ دیتابیس باید از قبل خالی و ساخته شده باشد.

اگر اطلاعات دیتابیس را در خود ویزارد وارد می‌کنید، متغیرهای `DB_DRIVER` و `DB_*` را در cPanel هم‌زمان تنظیم نکنید؛ متغیرهای محیطی بر تنظیم ذخیره‌شده اولویت دارند و پیکربندی ناقص می‌تواند مانع بالا آمدن برنامه شود. اگر عمداً از متغیرهای محیطی دیتابیس استفاده می‌کنید، همهٔ مقادیر لازم (`DB_DRIVER=mysql`، `DB_HOST`، `DB_NAME`، `DB_USER` و `DB_PASSWORD`) را کامل وارد کنید.

## ۶) اجرای ویزارد نصب

بعد از بالا آمدن برنامه، در مرورگر این نشانی را با HTTPS باز کنید:

```text
https://school.example.com/install
```

مراحل ویزارد:

1. مشخصات مدرسه را وارد کنید.
2. JSON یا MySQL را انتخاب کنید؛ برای MySQL اتصال را آزمایش کنید.
3. نام مدیر، شمارهٔ موبایل معتبر، نام کاربری و گذرواژه را وارد کنید. نام کاربری باید ۳ تا ۴۰ نویسهٔ مجاز انگلیسی باشد و گذرواژهٔ مدیر دست‌کم ۱۰ نویسه داشته باشد.
4. گزینهٔ **«نمونه‌داده‌های نمایشی حفظ شوند»** به‌صورت پیش‌فرض روشن است؛ برای مدرسهٔ واقعی آن را **خاموش** کنید تا رکوردهای نمونه وارد سامانه نشوند.
5. نصب را کامل کنید و با حساب مدیر تازه‌ساخته‌شده وارد شوید.

پس از نصب، مسیر `/install` و مسیرهای مستقیم فایل‌های ویزارد عمداً 404 می‌دهند. این رفتار طبیعی و بخشی از قفل امنیتی نصب است؛ برای دسترسی دوباره، فایل‌ها یا `DATA_DIR` را پاک نکنید.

## ۷) ورود پیامکی IPPanel (اختیاری)

ورود با گذرواژه پس از نصب قابل استفاده است. اگر پیامک OTP می‌خواهید، در پنل IPPanel یک API Key و الگوی فعال بسازید؛ سپس تنظیمات فرستنده، کد الگو و نام پارامتر کد را در تنظیمات مدیر وارد کنید. راه دیگر، تعریف متغیرهای زیر در Environment Variables برنامه است:

```text
IPPANEL_API_KEY
IPPANEL_FROM_NUMBER
IPPANEL_PATTERN_CODE
IPPANEL_OTP_PARAM
```

مقدارها را در مستند، Git یا فایل قابل دانلود قرار ندهید. متغیرهای محیطی بر تنظیمات پنل اولویت دارند؛ اگر می‌خواهید مدیر کلید را از پنل تنظیم کند، این متغیرها را تعریف نکنید. اتصال واقعی پیامک را با حساب IPPanel خود آزمایش کنید.

## ۸) بررسی نهایی و نگهداری

- صفحهٔ اصلی دامنه را باز کنید و با حساب مدیر وارد شوید.
- نشانی `https://school.example.com/api/health` باید پاسخ سالم بدهد: `{"status":"ok"}`.
- در تنظیمات مدرسه، سال تحصیلی، روزها و ساعت زنگ‌ها، کاربران و ماژول‌های لازم را بررسی کنید.
- HTTPS را فعال نگه دارید؛ گذرواژهٔ مدیر و حساب cPanel را یکتا و قوی انتخاب کنید.
- از وضعیت مدرسه پشتیبان بگیرید و یک نسخهٔ رمزگذاری‌شده را خارج از همان هاست نگه دارید. فایل `config.json` ممکن است حاوی اطلاعات اتصال باشد؛ آن را عمومی نکنید.
- پیش از هر به‌روزرسانی از داده‌ها پشتیبان بگیرید؛ سپس کد و وابستگی‌ها را به‌روزرسانی و برنامه را Restart کنید. پوشهٔ خصوصی `DATA_DIR` را با فایل‌های نسخهٔ جدید جایگزین نکنید.

## عیب‌یابی کوتاه

- **صفحهٔ 503 یا برنامه بالا نمی‌آید:** Node version، اجرای NPM Install، مسیر `server.js`، لاگ Passenger و متغیرهای cPanel را بررسی کنید.
- **ویزارد 404 می‌دهد:** احتمالاً برنامه قبلاً نصب شده یا `DATA_DIR` به دادهٔ نصب‌شده اشاره می‌کند؛ داده را پاک نکنید. برای نصب تازه، یک Application و `DATA_DIR` خالی و جدا بسازید.
- **اتصال MySQL ناموفق است:** پیشوند نام دیتابیس/کاربر، رمز، Host و دسترسی کامل کاربر را بررسی کنید.
- **خطای نوشتن فایل:** مالکیت پوشهٔ `DATA_DIR` باید متعلق به همان کاربر cPanel باشد و Node بتواند در آن بنویسد.
- **فایل‌های CSS یا API در زیرمسیر کار نمی‌کنند:** Application URL را به ریشهٔ دامنه/زیردامنه منتقل کنید.
