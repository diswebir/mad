# راهنمای نصب نسخهٔ دمو روی cPanel — فقط با رابط گرافیکی

این راهنما یک Application نمایشی جدا می‌سازد. برای نصب دمو به SSH یا Terminal نیاز ندارید؛ فایل‌ها را از File Manager بارگذاری می‌کنید و وابستگی‌ها را از دکمهٔ cPanel نصب می‌کنید.

> **هشدار جدی امنیتی:** حالت `DEMO_MODE=1` برای انتشار عمومیِ بدون محافظ مناسب نیست. صفحهٔ ورود حساب‌های یک‌کلیکی را نشان می‌دهد و بازدیدکننده می‌تواند وارد نقش‌های نمایشی، از جمله مدیر نمونه، شود و داده‌ها را تغییر دهد. دمو را فقط پشت یک لایهٔ دسترسی بیرونی که واقعاً صفحه و API را محافظت می‌کند قرار دهید. هرگز دادهٔ واقعی دانش‌آموز یا مدرسه وارد نکنید.

## تفاوت دمو با نسخهٔ عملیاتی

| دمو | نسخهٔ عملیاتی |
|---|---|
| `DEMO_MODE=1` فقط روی Application مستقل دمو | `DEMO_MODE` تعریف نمی‌شود |
| داده‌ها و حساب‌های نمونه | ویزارد نصب و حساب مدیر مدرسه |
| دادهٔ JSON در مسیر مستقل | JSON یا MySQL طبق نیاز مدرسه |
| `/install` عمداً غیرفعال | نصب نخست از `/install` انجام می‌شود |

**دمو را روی Application، دامنه، دیتابیس یا `DATA_DIR` نسخهٔ عملیاتی نصب نکنید.**

## ۱) ساخت زیردامنه و بستن دسترسی عمومی

1. در cPanel یک زیردامنهٔ جدا بسازید؛ نمونه: `demo.example.com`.
2. برای زیردامنه HTTPS را فعال کنید.
3. با **Directory Privacy** یا امکان مشابه هاست، دسترسی را به افراد مجاز محدود کنید. اگر در cPanel این امکان روی Node Application اعمال نمی‌شود، از پشتیبانی هاست بخواهید Basic Auth یا IP Allowlist را در لایهٔ وب‌سرور/پراکسی بگذارد.
4. در پنجرهٔ خصوصی مرورگر آزمایش کنید که هم صفحهٔ اصلی و هم `/api/health` قبل از ورود به محافظ، اجازهٔ دسترسی نمی‌دهند. اگر مسیر API محافظت نمی‌شود، دمو را منتشر نکنید.

مخفی‌کردن لینک یا انتخاب URL غیرقابل‌حدس جایگزین محافظ دسترسی نیست. گذرواژه‌های دمو در این راهنما و رابط سامانه دیده می‌شوند.

## ۲) بارگذاری کد با File Manager

در نسخهٔ فعلی این مخزن، کد کامل در شاخهٔ `arena/01a0f7fc-mad` است؛ اگر بعداً نسخه به شاخهٔ انتشار دیگری منتقل شد، همان شاخهٔ تأییدشده را انتخاب کنید.

1. در صفحهٔ GitHub مخزن `diswebir/mad` شاخهٔ `arena/01a0f7fc-mad` را انتخاب کنید.
2. روی **Code → Download ZIP** بزنید و فایل ZIP را به رایانه دانلود کنید.
3. در cPanel → **File Manager**، خارج از `public_html` یک پوشهٔ جدا برای کد بسازید؛ نمونه: `apps/madresehyar-demo`.
4. ZIP را Upload و Extract کنید. ZIP ممکن است یک پوشهٔ اضافی داشته باشد؛ در پایان Application root باید همان پوشه‌ای باشد که `server.js`، `package.json` و پوشه‌های `public`، `src` و `data` را مستقیماً در خود دارد.
5. `node_modules` یا فایل‌های دادهٔ نسخهٔ عملیاتی را کپی نکنید.

## ۳) ساخت مسیر دادهٔ خصوصی و جدا

در File Manager، داخل Home حساب یک پوشهٔ تازه بسازید، برای نمونه:

```text
/home/CPANEL_USER/private/madresehyar-demo-data
```

`CPANEL_USER` را با نام حساب cPanel جایگزین کنید. مسیر واقعی Home در بالای File Manager یا از پشتیبانی هاست قابل مشاهده است. پوشه را بیرون از `public_html` بسازید؛ روی آن راست‌کلیک کنید و از **Permissions / Change Permissions**، اگر در دسترس است، مجوز `0700` (فقط دسترسی مالک) بدهید. از `777` استفاده نکنید.

این پوشه باید با `DATA_DIR` نسخهٔ عملیاتی متفاوت باشد. دمو را به MySQL عملیاتی وصل نکنید.

## ۴) ساخت Node.js Application دمو در cPanel

1. وارد **Setup Node.js App → Create Application** شوید.
2. نسخهٔ LTS پشتیبانی‌شدهٔ Node را انتخاب کنید؛ حداقل نیاز پروژه `18.17` است.
3. **Application mode** را `Production` قرار دهید. این گزینه با فعال‌کردن داده‌های دمو تعارض ندارد؛ فعال‌سازی دمو فقط از متغیر `DEMO_MODE` انجام می‌شود.
4. **Application root** را روی پوشهٔ کدی بگذارید که مستقیماً `server.js` دارد؛ نمونه: `apps/madresehyar-demo`.
5. **Application URL** را روی ریشهٔ `demo.example.com` بگذارید، نه زیرمسیر دامنه.
6. **Application startup file** را دقیقاً `server.js` وارد کنید.
7. در **Environment variables / Add Variable** همین Application، مقادیر زیر را ثبت کنید:

| نام | مقدار نمونه |
|---|---|
| `DEMO_MODE` | `1` |
| `DATA_DIR` | `/home/CPANEL_USER/private/madresehyar-demo-data` |

   **Application mode باید Production باقی بماند**؛ حالت دادهٔ دمو جداگانه با `DEMO_MODE=1` فعال می‌شود. بسیاری از نسخه‌های cPanel، `NODE_ENV=production` را از Application mode تنظیم می‌کنند. اگر هاست این کار را نمی‌کند، `NODE_ENV=production` را فقط در صورت نبودن مقدار موجود اضافه کنید. اگر امکان دارید، متغیرها را هنگام ساخت Application وارد کنید؛ در غیر این صورت بلافاصله در صفحهٔ Edit اضافه و ذخیره‌شان کنید. `.env` خودکار خوانده نمی‌شود. `DEMO_MODE=1` را روی هیچ Application دیگری نگذارید.

8. در **Setup Node.js App → Edit → Run NPM Install** وابستگی‌ها را نصب و منتظر پیام موفقیت بمانید. این مرحله از رابط وب انجام می‌شود و به دستور ترمینال نیاز ندارد.
9. از همان صفحه برنامه را **Restart** کنید. cPanel پورت `PORT` را مدیریت می‌کند؛ پورت دیگری در تنظیمات وارد نکنید.

متغیرهای `DB_DRIVER`، `DB_HOST`، `DB_NAME`، `DB_USER`، `DB_PASSWORD` و هر متغیر IPPanel را برای دمو تعریف نکنید. حالت پیش‌فرض، دادهٔ JSON نمونه است.

## ۵) بازکردن دمو

پس از اینکه وضعیت Application در cPanel `Started` شد، محافظ دسترسی را روشن نگه دارید و نشانی زیر را باز کنید:

```text
https://demo.example.com/
```

حساب‌های نمایشی:

| نقش | نام کاربری | گذرواژه |
|---|---|---|
| مدیر مدرسه | `admin` | `admin123` |
| معلم | `ahmadi` | `teacher123` |
| دانش‌آموز | `sara` | `student123` |
| ولی دانش‌آموز | `maryam` | `parent123` |

در صفحهٔ ورود دکمهٔ ورود یک‌کلیکی هم وجود دارد. این حساب‌ها واقعی یا خصوصی نیستند و برای امنیت دمو نباید به آن‌ها تکیه کرد. دمو را به پیامک واقعی، اطلاعات واقعی، کلیدهای واقعی IPPanel یا دیتابیس مدرسه وصل نکنید.

در حالت دمو ویزارد نصب و آزمون دیتابیس غیرفعال‌اند؛ بنابراین 404 روی `/install` طبیعی است. برای سلامت برنامه، `/api/health` باید `{"status":"ok"}` بدهد، اما این مسیر هم باید زیر همان محافظ دسترسی بیرونی باشد.

## ۶) اگر دمو هم 503 می‌دهد

از cPanel → **Setup Node.js App → Edit** این موارد را با رابط وب بررسی کنید:

1. وضعیت Application باید `Started` باشد؛ در غیر این صورت Restart کنید.
2. Application root باید همان پوشه‌ای باشد که `server.js` و `package.json` را مستقیماً دارد.
3. Startup file دقیقاً `server.js` باشد و Node نسخهٔ `18.17` یا جدیدتر انتخاب شده باشد.
4. **Run NPM Install** باید بدون خطا تمام شود.
5. `DATA_DIR` را بازبینی کنید؛ پوشه باید خارج از `public_html` و قابل‌نوشتن برای کاربر Node باشد. هیچ متغیر `DB_*` یا IPPanel در این Application نمانده باشد.
6. اگر هنوز 503 است، از فیلد **Passenger log file** در صفحهٔ Edit (اگر موجود است) یا **cPanel → Metrics → Errors** لاگ را ببینید. اگر لاگ در دسترس نیست، از پشتیبانی هاست بخواهید Passenger/Node application error log را بررسی کند و فعال‌بودن Node.js Selector، Passenger و متغیر `PORT` را تأیید کند.

اگر تنها خط لاگ شما `INFO ... set restart marker to .../tmp/restart.txt` است، این پیام اطلاع‌رسانی Passenger است، نه خطای واقعی برنامه؛ [راهنمای نصب عملیاتی](cpanel-install-fa.md) هم بخش عیب‌یابی 503 بدون SSH دارد و توضیح می‌دهد لاگ خطا را از کجا پیدا کنید. اطلاعات دمو را برای حل 503 پاک نکنید؛ ابتدا مسیرها و لاگ را بررسی کنید.

## ۷) بازنشانی دادهٔ دمو بدون حذف فایل‌ها

تغییرهای بازدیدکنندگان ممکن است بعد از Restart هم باقی بماند. برای شروع دوباره از دادهٔ نمونه:

1. برنامهٔ دمو را در Setup Node.js App متوقف کنید.
2. در File Manager یک پوشهٔ دادهٔ جدید و خالی، مخصوص همین دمو، بسازید؛ مثلاً `private/madresehyar-demo-data-reset-new`.
3. در Setup Node.js App → Edit، فقط مقدار `DATA_DIR` همین Application دمو را به مسیر کامل پوشهٔ تازه تغییر دهید و ذخیره کنید.
4. برنامه را Restart کنید؛ دادهٔ نمونه در مسیر جدید ایجاد می‌شود. پوشهٔ قدیمی را فعلاً نگه دارید تا چیزی ناخواسته حذف نشود.

## چک‌لیست پیش از ارائه

- [ ] HTTPS روی زیردامنه فعال است.
- [ ] `DEMO_MODE=1` فقط روی Application دمو تنظیم شده است.
- [ ] کد و `DATA_DIR` دمو مستقل از تولید هستند.
- [ ] Run NPM Install موفق بوده و Application در cPanel `Started` است.
- [ ] محافظ بیرونی، صفحه و API را پوشش می‌دهد و در مرورگر خصوصی آزمایش شده است.
- [ ] هیچ دادهٔ واقعی یا اعتبارنامهٔ واقعی در دمو وجود ندارد.
