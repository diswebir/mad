# مدرسه‌یار — سامانه مدیریت مدرسه با Node.js · نسخه ۱.۱.۰

مدرسه‌یار یک پنل فارسی و راست‌چین ماژولار برای مدیریت مدرسه، معلم‌ها، کلاس‌ها و پرونده دانش‌آموزان است. نسخهٔ ۱.۱.۰ گردش‌کار سریع حضور گروهی، کنترل تداخل برنامه، تنظیمات منطقهٔ زمانی، پشتیبان‌گیری و بازیابی امن و نقش‌های سفارشی را تکمیل می‌کند. برنامه با Node.js و بدون فریم‌ورک فرانت‌اند ساخته شده، معماری MVC/لایه‌ای دارد و برای اجرای Node.js در cPanel آماده است. رابط کاربری از فونت **Vazirmatn** استفاده می‌کند و برای حالت نمایشی، داده نمونه واقعی دارد. فایل‌های فونت WOFF2 در خود پروژه قرار دارند (مجوز SIL Open Font License) و برای نمایش فارسی به سرویس بیرونی وابسته نیستند.

## اجرای محلی

نیازمندی: Node.js نسخه ۱۸.۱۷ یا بالاتر و npm.

```bash
npm install
npm run dev
```

سپس `http://localhost:3000` را باز کنید. در حالت `dev` برنامه با داده‌های نمونه و ورود نمایشی اجرا می‌شود.

### حساب‌های نمونه

| نقش | نام کاربری | گذرواژه |
|---|---|---|
| مدیر مدرسه | `admin` | `admin123` |
| معلم | `ahmadi` | `teacher123` |
| دانش‌آموز | `sara` | `student123` |
| ولی دانش‌آموز | `maryam` | `parent123` |

این گذرواژه‌ها فقط برای محیط نمایشی هستند. از `npm run dev` یا `DEMO_MODE=1` روی هاست عمومی استفاده نکنید.

## نصب روی cPanel

1. فایل‌های پروژه را در پوشه‌ای از حساب هاست (ترجیحاً خارج از `public_html`) بارگذاری و استخراج کنید.
2. در **cPanel → Setup Node.js App** یک برنامه بسازید و Node.js 18 یا جدیدتر، مسیر ریشه پروژه و فایل شروع `server.js` را انتخاب کنید.
3. از **Run NPM Install** در cPanel یا Terminal دستور زیر را اجرا کنید:
   ```bash
   npm install
   ```
4. برنامه را راه‌اندازی/Restart کنید. برنامه روی `0.0.0.0` و پورتی که cPanel در `PORT` می‌دهد گوش می‌کند.
5. نشانی دامنه به‌همراه `/install` را باز کنید و ویزارد سه‌مرحله‌ای را کامل کنید:
   - مشخصات مدرسه؛
   - انتخاب ذخیره‌سازی JSON یا MySQL؛
   - ساخت حساب مدیر با گذرواژه قوی.
6. پس از پایان نصب، از صفحه اصلی وارد پنل شوید. ویزارد نصب برای سامانه نصب‌شده قفل می‌شود.

### انتخاب پایگاه داده

- **فایل محلی JSON:** راه‌اندازی بدون تنظیمات دیتابیس؛ اطلاعات در `data/state.json` و به‌روزرسانی‌ها به‌صورت اتمیک ذخیره می‌شوند. برای دمو، توسعه و مدرسه‌های کوچک مناسب است. از این فایل نسخه پشتیبان بگیرید.
- **MySQL/MariaDB:** ابتدا در cPanel یک Database و Database User بسازید، کاربر را با دسترسی کامل به همان دیتابیس متصل کنید و سپس اطلاعات را در ویزارد وارد کنید. اتصال قبل از نصب بررسی می‌شود. برنامه ساختار جدول‌ها را ایجاد می‌کند؛ خود دیتابیس باید از قبل در cPanel ساخته شده باشد. تنظیمات اتصال در `data/config.json` با دسترسی محدود ذخیره می‌شود؛ این فایل در Git نادیده گرفته شده است.

در نصب واقعی و روی هاست عمومی، از حسابی که ویزارد ساخته استفاده کنید؛ حساب‌های نمونه فقط در اجرای نمایشی ساخته می‌شوند. سرور Node را با `NODE_ENV=production` اجرا کنید و از انتشار پوشه `data` به‌عنوان فایل استاتیک خودداری کنید.

## قابلیت‌های نسخهٔ ۱.۱.۰

سامانه از **۲۵ ماژول مستقل** تشکیل شده است. مدیر می‌تواند از «مدیریت ماژول‌ها» قابلیت‌های غیرضروری را خاموش و هر زمان دوباره فعال کند. داشبورد، پرونده دانش‌آموز، معلم و کلاس‌ها و بخش تنظیمات/مدیریت ماژول‌ها زیربنایی هستند و خاموش نمی‌شوند تا فرم‌ها و ارتباط داده‌های مدرسه از کار نیفتند. دارایی‌های اصلی رابط نیز با شناسهٔ نسخه cache-bust می‌شوند تا استقرار جدید فایل‌های قدیمی مرورگر را نگه ندارد.

1. داشبورد مدیریتی و شاخص‌های روزانه؛
2. پرونده کامل دانش‌آموز و اطلاعات تماس ولی/اضطراری؛
3. مدیریت معلم و تخصص آموزشی؛
4. مدیریت کلاس، ظرفیت، اتاق و تعیین معلم مسئول؛
5. پرونده و راه‌های تماس اولیا؛
6. حضور و غیاب روزانه، تأخیر، غیبت و مرخصی؛
7. درس‌ها و ساعات هفتگی؛
8. برنامه هفتگی کلاس‌ها؛
9. تکالیف و مهلت تحویل؛
10. برنامه آزمون‌ها؛
11. ثبت نمره و مشاهده کارنامه؛
12. تیکت گفت‌وگو بین مدرسه، معلم، دانش‌آموز و ولی؛
13. اطلاعیه‌های مدرسه؛
14. تقویم ماهانه مدرسه، جلسه‌ها و اردوها؛ نمایش برنامه روزانه کلاس‌ها با فیلتر پایه و ساعت هر زنگ؛
15. سوابق پیام‌رسانی؛
16. شهریه، اقساط و وضعیت پرداخت؛
17. فهرست و موجودی کتابخانه؛
18. مسیرهای سرویس مدرسه؛
19. اسناد و فایل‌های مدرسه؛
20. گزارش‌های مدیریتی؛
21. حساب‌های کاربران با نقش مدیر/معلم/دانش‌آموز/ولی؛
22. نقش‌ها و سطوح دسترسی؛
23. گزارش تغییرات و فعالیت کاربران؛
24. تنظیمات و مشخصات مدرسه؛
25. روشن/خاموش کردن ماژول‌ها.

فرم ساخت دانش‌آموز یا معلم می‌تواند هم‌زمان حساب پنل مربوطه را نیز ایجاد کند. دسترسی هر حساب بر اساس نقش محدود است؛ معلم داده کلاس خودش را می‌بیند و دانش‌آموز/ولی به پرونده مرتبط با خود دسترسی دارند. تیکت‌ها تاریخچه پیام دارند و مدیر می‌تواند آن‌ها را ببندد.

### تغییرات نسخهٔ ۱.۱.۰

- **ثبت سریع حضور معلم:** کلاس و تاریخ را انتخاب کنید؛ همهٔ دانش‌آموزان فعال فهرست می‌شوند و پیش‌فرض حضور است. معلم فقط غایبان را با سوئیچر مشخص می‌کند. ذخیرهٔ دوباره همان رکوردهای همان روز را اصلاح می‌کند و رکورد تکراری نمی‌سازد. کنترل کلاس‌های مجاز و فهرست شناسه‌های ارسالی در سمت سرور انجام می‌شود.
- **برنامهٔ هفتگی بدون هم‌پوشانی:** بازه‌های ساعت فارسی/لاتین و روز هفته عادی‌سازی می‌شوند؛ هم‌زمانی یک کلاس، معلم یا اتاق برای دو زنگ رد می‌شود. برنامهٔ نمونه نیز ممیزی شده تا تداخل اولیه نداشته باشد.
- **تاریخ/منطقهٔ زمانی:** منطقهٔ زمانی IANA مدرسه در تنظیمات تعیین می‌شود و برای تاریخ امروز، ساعت ثبت و نمودار هفتگی به کار می‌رود. تاریخ‌های تقویمی فقط با جابه‌جایی timezone به روز دیگری منتقل نمی‌شوند.
- **انتخاب‌گرهای بزرگ:** گزینه‌های فرم از API به‌صورت صفحه‌بندی‌شده بارگیری می‌شوند؛ انتخاب پرونده بین بیش از ۱۰۰ رکورد نیز محدود به صفحهٔ اول نیست.
- **پشتیبان و بازیابی:** از بخش تنظیمات مدیر می‌تواند پشتیبان بسازد/دانلود کند یا فایل JSON را بازیابی کند. فایل‌ها در پوشهٔ دادهٔ خصوصی با مجوز محدود نگهداری می‌شوند؛ پشتیبان شامل هش گذرواژه‌هاست و باید محرمانه بماند. بازیابی به نقش مدیر و گذرواژهٔ فعلی نیاز دارد، قالب/ساختار را اعتبارسنجی می‌کند، پیش از جایگزینی پشتیبان ایمنی می‌سازد و نشست‌ها را می‌بندد. نسخهٔ خودکار هنگام راه‌اندازی و سپس هر ۲۴ ساعت ساخته می‌شود و ۱۴ نسخهٔ اخیر باقی می‌ماند. این سازوکار جای نسخهٔ جداگانهٔ خارج از هاست را نمی‌گیرد.
- **نقش‌ها و دسترسی:** دسترسی ماژول، مشاهده و نوشتن نقش‌های معلم/دانش‌آموز/ولی قابل تنظیم است. مدیر می‌تواند نقش سفارشی (مثلاً معاون یا حسابدار) بسازد؛ ماژول‌ها و دسترسی داده را صریحاً انتخاب کند و نقش را به کل مدرسه یا کلاس‌های مشخص محدود کند. مسیرهای مدیر، کاربران، گزارش فعالیت، تنظیمات و مدیریت ماژول‌ها به نقش سفارشی واگذار نمی‌شوند. نقش دارای حساب کاربری تا زمان انتقال حساب‌ها حذف نمی‌شود.

ارتباط با پیامک، درگاه پرداخت، سرویس ابری یا سامانهٔ احراز هویت بیرونی در این نسخه ادعا نمی‌شود؛ برای اتصال واقعی به آن‌ها باید اعتبارنامه و ارائه‌دهندهٔ مربوط در محیط نصب پیکربندی شود. سوابق پیام‌رسانی و مالی فعلی داخلی هستند و به‌تنهایی ارسال پیامک یا تراکنش بانکی انجام نمی‌دهند.

## ساختار پروژه (MVC/لایه‌ای)

```text
server.js                         # نقطه ورود، HTTP server و سرو فایل‌ها
src/config.js                     # خواندن تنظیمات امن و متغیرهای محیطی
src/controllers/apiController.js  # کنترلر احراز هویت، نصب و API ماژول‌ها
src/models/store.js               # مدل ذخیره‌سازی JSON با نوشتن اتمیک
src/models/mysqlStore.js          # مدل MySQL/MariaDB
src/data/modules.js               # تعریف ماژول‌ها و دسترسی نقش‌ها
src/data/seed.js                  # راه‌اندازی داده‌های اولیه و کاربران دمو
src/lib/security.js               # هش گذرواژه و ابزارهای امنیتی
src/lib/dates.js                  # تاریخ مدرسه، timezone و اعتبارسنجی ISO
src/lib/backupManager.js          # پشتیبان‌گیری، اعتبارسنجی restore و نگهداری امن
public/                            # رابط فارسی RTL، CSS و JavaScript
public/fonts/                      # فایل‌های WOFF2 فونت Vazirmatn و مجوز OFL
data/seed.json                     # داده‌های نمونه غیرحساس
```

در MySQL، رکوردها در جدول دارای کلید مرکب «مجموعه/شناسه» و payload از نوع JSON ذخیره می‌شوند؛ تغییرات فقط برای رکوردهای تغییریافته نوشته می‌شوند. نسخه فعلی برای یک مدرسه و اجرای تک‌نمونه‌ای Node طراحی شده است؛ برای استقرار چندنمونه‌ای/ترافیک بالا، مرحله بعدی باید نشست اشتراکی (مثلاً Redis) و گزارش‌گیری/صفحه‌بندی مستقیم SQL را اضافه کند.

## تنظیمات و آزمون

- متغیرهای محیطی دیتابیس: `DB_DRIVER=mysql`، `DB_HOST`، `DB_PORT`، `DB_NAME`، `DB_USER`، `DB_PASSWORD`.
- مسیر داده قابل تغییر است: `DATA_DIR=/path/to/private-data`.
- بررسی نحو فایل‌ها و اجرای آزمون‌های یکپارچگی API برای دسترسی نقش‌های پیش‌فرض/سفارشی، محدودهٔ کلاس، حضور گروهی، تداخل برنامه، پشتیبان/بازیابی، timezone و ذخیره‌ساز (در حال حاضر ۱۰ آزمون):
  ```bash
  npm run check
  npm test
  ```
- فایل‌های `data/state.json`، `data/config.json` و پوشهٔ `data/backups/` را به وب‌سرور استاتیک معرفی نکنید. در محیط تولید حالت دمو را خاموش نگه دارید، HTTPS را فعال کنید و پشتیبان قابل‌بازیابی را جدا از هاست نیز نگهداری کنید.
- فایل `data/seed.json` داده‌های نمونه دانش‌آموز، معلم، کلاس، حضور و غیاب، تیکت، تکلیف، نمره، شهریه، اطلاعیه و ... را شامل می‌شود. در ویزارد می‌توان حفظ یا پاک‌سازی این داده‌های نمایشی را انتخاب کرد.

## APIهای اصلی

- احراز هویت و راه‌اندازی: `/api/auth/login`، `/api/auth/me`، `/api/auth/logout`، `/api/bootstrap` و `/api/install`؛
- داده‌های ماژول‌ها: `/api/records/:module` با فیلتر و صفحه‌بندی؛
- حضور سریع: `GET` و `POST /api/attendance/class/:classId`؛ بدنهٔ ذخیره `{ "date": "YYYY-MM-DD", "absentIds": ["student-id"] }`؛
- دسترسی: `GET /api/records/roles` و مسیرهای مدیر `POST /api/roles`، `PATCH /api/roles/:id` و `DELETE /api/roles/:id`؛
- تنظیمات و ماژول‌ها: `/api/settings` و `/api/modules/:id`؛
- نسخهٔ پشتیبان مدیر: `/api/admin/backups`، `/api/admin/backups/:filename` و `POST /api/admin/restore`.

تمام مسیرهای مدیریت به نشست معتبر و مجوز نقش در سمت سرور وابسته‌اند؛ پنهان‌کردن منو به‌تنهایی مرز امنیتی محسوب نمی‌شود.
