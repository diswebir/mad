# راهنمای نصب نسخهٔ عملیاتی مدرسه‌یار روی cPanel — بدون SSH

این راهنما برای نصب نسخهٔ واقعی سامانه از رابط cPanel است و عمداً به SSH یا Terminal وابسته نیست. عنوان دکمه‌ها ممکن است بین شرکت‌های هاست متفاوت باشد.

> **مهم:** برای نسخهٔ عملیاتی، `DEMO_MODE=1` را تنظیم نکنید و `npm run dev` را اجرا نکنید. حساب‌های دمو عمومی‌اند.

## پیش از شروع

- هاست باید قابلیت **Setup Node.js App** یا **Node.js Selector** را داشته باشد. اگر این گزینه در cPanel شما نیست، فقط پشتیبانی هاست می‌تواند Node.js/Passenger را فعال کند.
- Node.js انتخابی باید حداقل `18.17` باشد؛ در صورت امکان نسخهٔ LTS پشتیبانی‌شدهٔ جدیدتر را انتخاب کنید.
- یک دامنه یا زیردامنهٔ فعال و گواهی HTTPS لازم است.
- این برنامه برای یک مدرسه و یک اجرای Node طراحی شده است؛ چند Application را به یک فایل داده وصل نکنید.
- Application URL را روی ریشهٔ یک دامنه/زیردامنه بگذارید، مانند `https://school.example.com/`. برنامه مسیرهای ریشه‌دار مثل `/api` دارد و برای نصب زیرمسیرهایی مانند `/mad` تنظیم نشده است.

## ۱) دانلود و بارگذاری فایل‌ها با cPanel File Manager

در نسخهٔ فعلی این مخزن، کد کامل در شاخهٔ `arena/01a0f7fc-mad` است؛ اگر بعداً نسخه در شاخهٔ انتشار دیگری قرار گرفت، همان شاخهٔ تأییدشده را انتخاب کنید.

1. در مرورگر وارد GitHub و صفحهٔ مخزن `diswebir/mad` شوید.
2. از انتخاب‌گر شاخه، `arena/01a0f7fc-mad` را انتخاب کنید و از منوی **Code → Download ZIP** فایل را روی رایانه بگیرید.
3. وارد cPanel → **File Manager** شوید. پوشهٔ برنامه را در Home بسازید، نه در `public_html`؛ برای نمونه `apps/madresehyar`.
4. ZIP را در آن پوشه بارگذاری و با دکمهٔ **Extract** باز کنید.
5. ZIP گیت‌هاب معمولاً یک پوشهٔ اضافی درون خود دارد. در File Manager، پوشه‌ای را پیدا کنید که `server.js`، `package.json` و پوشه‌های `public`، `src` و `data` درون آن هستند. **Application root در مرحلهٔ بعد باید دقیقاً همین پوشه باشد.** وجود `server.js` یک پوشه پایین‌تر از Application root یکی از علت‌های رایج 503 است.
6. `node_modules` را بارگذاری نکنید؛ cPanel آن را از روی `package.json` نصب می‌کند.

## ۲) ساخت پوشهٔ دادهٔ خصوصی با File Manager

1. در Home cPanel یک پوشهٔ جدا، بیرون از `public_html`، بسازید؛ نمونه: `private/madresehyar-data`.
2. مسیر کامل را یادداشت کنید؛ نمونه: `/home/CPANEL_USER/private/madresehyar-data` (به‌جای `CPANEL_USER` نام حساب خودتان را بگذارید). اگر مسیر Home را نمی‌دانید، از نوار مسیر File Manager یا پشتیبانی هاست بپرسید.
3. در File Manager روی پوشه راست‌کلیک و **Permissions / Change Permissions** را باز کنید. اگر امکانش هست مجوز پوشه را `0700` بگذارید: مالک دسترسی کامل داشته باشد و دسترسی گروه/عموم بسته باشد. از مجوز `777` استفاده نکنید.

برنامه فایل داده، تنظیمات و پشتیبان را در `DATA_DIR` نگه می‌دارد. این پوشه را با ریشهٔ سایت یا دمو مشترک نکنید.

## ۳) ساخت Node.js Application از رابط cPanel

1. در cPanel وارد **Setup Node.js App** شوید و **Create Application** را بزنید.
2. نسخهٔ Node.js را انتخاب کنید (حداقل `18.17`؛ ترجیحاً LTS پشتیبانی‌شدهٔ جدیدتر).
3. **Application mode** را `Production` انتخاب کنید.
4. در **Application root** مسیر پوشه‌ای را وارد کنید که در مرحلهٔ ۱ مستقیماً `server.js` دارد؛ معمولاً `apps/madresehyar`، نسبت به Home حساب.
5. در **Application URL**، دامنه/زیردامنهٔ موردنظر را انتخاب و مسیر اضافی را خالی بگذارید تا برنامه در ریشهٔ دامنه باز شود.
6. در **Application startup file** دقیقاً `server.js` بنویسید.
7. برنامه را ایجاد کنید. اگر صفحه بلافاصله 503 نشان داد، تا پایان نصب وابستگی‌ها و Restart ادامه دهید؛ این خطا پیش از آماده‌شدن Application به‌تنهایی تشخیص نهایی نیست.

## ۴) متغیرهای محیطی و نصب وابستگی‌ها — بدون دستور ترمینال

در **Setup Node.js App → Edit** همان برنامه، بخش **Environment variables / Add Variable** را باز کنید و این مقدار را اضافه کنید:

| نام | مقدار نمونه |
|---|---|
| `DATA_DIR` | `/home/CPANEL_USER/private/madresehyar-data` |

نام کاربر و مسیر را با مقادیر واقعی هاست خود عوض کنید. Application mode در حالت Production باشد؛ در بسیاری از نسخه‌های Node.js Selector مقدار `NODE_ENV=production` از همین انتخاب تنظیم می‌شود. اگر cPanel آن را خودکار تنظیم نمی‌کند، `NODE_ENV=production` را فقط در صورت نبودن مقدار موجود اضافه کنید و متغیر تکراری نسازید. `DEMO_MODE` را اضافه نکنید؛ اگر از قبل وجود دارد، حذفش کنید. برنامه فایل `.env` را خودکار نمی‌خواند، پس `DATA_DIR` را در همین بخش cPanel ثبت کنید.

سپس در همان صفحهٔ **Edit**:

1. بخش **Run NPM Install** را پیدا و اجرا کنید.
2. منتظر پیام موفقیت نصب بمانید. اگر خطا می‌دهد، قبل از Restart آن را رفع کنید؛ نصب ناقص وابستگی‌ها معمولاً باعث می‌شود برنامه اصلاً بالا نیاید.
3. برنامه را با دکمهٔ **Restart** راه‌اندازی کنید. اگر فقط **Stop/Start** دارید، Stop بزنید، کمی صبر کنید و Start کنید.

**هیچ دستور SSH لازم نیست.** اگر دکمهٔ Run NPM Install دیده نمی‌شود یا `package.json` شناسایی نشده، معمولاً Application root اشتباه است یا `package.json` مستقیماً داخل همان پوشه نیست.

cPanel/Passenger پورت برنامه را مدیریت می‌کند و کد سامانه از `PORT` استفاده می‌کند؛ پورت را دستی در تنظیمات یا `.htaccess` ثابت نکنید. فایل `.htaccess` ساخته‌شده توسط cPanel را هم برای رفع 503 دستی جایگزین یا حذف نکنید.

## ۵) انتخاب JSON یا MySQL

### نصب ساده با JSON

در ویزارد نصب JSON را انتخاب کنید؛ نیازی به ساخت دیتابیس نیست و فایل وضعیت در `DATA_DIR/state.json` ذخیره می‌شود. این روش برای شروع یا استفادهٔ کم‌حجم است. از داده‌ها نسخهٔ پشتیبان جداگانه داشته باشید.

### نصب با MySQL/MariaDB

1. در cPanel بخش **MySQL Databases** یا **MySQL Database Wizard** را باز کنید.
2. دیتابیس و کاربر بسازید و کاربر را با **ALL PRIVILEGES** به همان دیتابیس متصل کنید.
3. نام کامل دیتابیس و کاربر را یادداشت کنید؛ cPanel معمولاً پیشوند حساب را به آن‌ها اضافه می‌کند.
4. در مرحلهٔ پایگاه دادهٔ ویزارد مدرسه‌یار، MySQL را انتخاب و اطلاعات را وارد کنید. Host معمولاً `localhost` و Port معمولاً `3306` است؛ مقدار قطعی را از شرکت هاست بپرسید.
5. دکمهٔ **بررسی اتصال** را بزنید و فقط در صورت موفقیت ادامه دهید. خود ویزارد جدول‌ها را می‌سازد؛ دیتابیس باید از قبل ساخته و برای نصب تازه خالی باشد.

اگر اطلاعات اتصال را در ویزارد وارد می‌کنید، متغیرهای `DB_DRIVER` و `DB_*` را در cPanel اضافه نکنید. متغیر محیطی بر تنظیم ذخیره‌شده اولویت دارد و مقدار ناقص می‌تواند باعث خطای آغاز برنامه شود.

## ۶) تکمیل ویزارد مدرسه

بعد از Restart موفق، نشانی دامنه را با HTTPS باز کنید و سپس `/install` را به انتهای آن اضافه کنید؛ نمونه:

```text
https://school.example.com/install
```

1. مشخصات مدرسه را وارد کنید.
2. JSON یا MySQL را انتخاب کنید؛ اگر MySQL است، اتصال را آزمایش کنید.
3. حساب مدیر بسازید: شمارهٔ موبایل معتبر اجباری است؛ نام کاربری ۳ تا ۴۰ نویسهٔ مجاز انگلیسی و گذرواژه دست‌کم ۱۰ نویسه باشد.
4. گزینهٔ **«نمونه‌داده‌های نمایشی حفظ شوند»** پیش‌فرض روشن است؛ برای مدرسهٔ واقعی خاموشش کنید.
5. نصب را کامل کنید و با حساب مدیر خودتان وارد شوید.

پس از نصب، `/install` و فایل‌های مستقیم ویزارد عمداً 404 می‌شوند؛ این رفتار امنیتی طبیعی است و به معنی خرابی نیست. برای نصب دوباره داده‌ها را پاک نکنید؛ از پشتیبان و راهکار نصب جداگانه استفاده کنید.

## ۷) عیب‌یابی 503 بدون SSH

**503 یعنی وب‌سرور نتوانسته برنامهٔ Node را اجرا کند یا به آن وصل شود.** معمولاً قبل از رسیدن درخواست به ویزارد رخ می‌دهد؛ بنابراین با تغییر اطلاعات فرم نصب حل نمی‌شود. این ترتیب را از رابط cPanel بررسی کنید:

1. **Application Status:** در Setup Node.js App ببینید برنامه `Started` است. اگر نیست، Edit و سپس Restart را بزنید.
2. **مسیر و فایل شروع:** Application root را بازبینی کنید؛ همان پوشه باید `server.js`، `package.json` و `src` را مستقیماً داشته باشد. Startup file دقیقاً `server.js` باشد.
3. **نسخهٔ Node:** نسخه باید حداقل `18.17` باشد و در فهرست هاست واقعاً نصب/فعال باشد. اگر این نسخه در فهرست نیست، از پشتیبانی هاست نسخهٔ سازگار بخواهید.
4. **NPM Install:** در Edit روی Run NPM Install بزنید و نتیجهٔ موفق را ببینید. اگر پیام `Cannot find module` یا خطای وابستگی دارد، نصب از روی Application root درست انجام نشده است.
5. **Environment Variables:** اگر نصب JSON می‌خواهید، `DB_DRIVER=mysql` و متغیرهای DB را حذف کنید. اگر `DB_DRIVER=mysql` مانده ولی Host، نام دیتابیس یا کاربر ناقص است، برنامه هنگام شروع متوقف می‌شود. مقدار `DATA_DIR` نیز باید مسیر واقعی و قابل‌نوشتن باشد.
6. **لاگ‌ها:** در Setup Node.js App → Edit، اگر فیلد **Passenger log file** وجود دارد مسیرش را یادداشت و همان فایل را در File Manager باز کنید. اگر مسیر لاگ مشخص نیست، در cPanel بخش **Metrics → Errors** را بررسی کنید. عنوان و محل لاگ بسته به شرکت هاست فرق می‌کند.
7. **مشکل باقی است؟** تصویر صفحهٔ تنظیمات برنامه (بدون نمایش گذرواژه‌ها)، متن خطای NPM Install و زمان رخداد را برای پشتیبانی هاست بفرستید و بخواهید **Passenger/Node application error log** را بررسی کند؛ همچنین بپرسید Node.js Selector و Passenger برای حساب شما فعال است و متغیر `PORT` به برنامه می‌رسد یا نه.

اگر صفحهٔ اصلی باز می‌شود ولی `/install` پس از نصب 404 است، برنامه نصب شده است؛ 404 در این مسیر مورد انتظار است. اگر هنوز نصب نشده‌اید، Application URL و وضعیت `DATA_DIR` را بررسی کنید و پوشهٔ دادهٔ تولید را پاک نکنید.

## ۸) بعد از نصب

- نشانی `https://school.example.com/api/health` باید `{"status":"ok"}` برگرداند.
- HTTPS را فعال نگه دارید و گذرواژهٔ مدیر و cPanel را قوی و یکتا انتخاب کنید.
- فایل `config.json` حاوی تنظیمات حساس اتصال است؛ `DATA_DIR` یا فایل‌های آن را داخل `public_html` نگذارید و برای پشتیبان‌گیری عمومی منتشر نکنید.
- ورود پیامکی IPPanel اختیاری است. API Key را فقط در تنظیمات مدیر یا Environment Variables همین Application وارد کنید؛ متغیرهای محیطی بر تنظیمات پنل اولویت دارند.
- پیش از به‌روزرسانی از وضعیت پشتیبان بگیرید. کد را از File Manager/ZIP به‌روز کنید، Run NPM Install و Restart را اجرا کنید؛ پوشهٔ خصوصی `DATA_DIR` را با فایل‌های کد جایگزین نکنید.
